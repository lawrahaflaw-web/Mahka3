# مَحكى — النسخة الثابتة (GitHub Pages)

هذه نسخة من موقع مَحكى مصمَّمة خصيصًا لتُنشر مجانًا وبسهولة على GitHub Pages،
بدون خادم Python منفصل. لوحة التحكم تحفظ كل تعديل مباشرة داخل مستودع GitHub
عبر GitHub API — تبقين تديرين الموقع من واجهة، بدون فتح أي كود.

## الفرق عن النسخة الكاملة (Flask)

| الميزة | نسخة Flask | هذه النسخة (ثابتة) |
|---|---|---|
| الاستضافة | تحتاج خادم يعمل باستمرار (Render وغيره) | GitHub Pages مجاني ودائم بدون نوم |
| قاعدة البيانات | SQLite حقيقية | ملفات JSON داخل المستودع |
| حفظ التعديلات | فوري في قاعدة البيانات | Commit مباشر لملفات JSON عبر GitHub API |
| حجم الصوت الأقصى | 80MB | 25MB (لأن الرفع يمر من متصفحك مباشرة) |
| عداد الاستماع | تلقائي لكل زيارة حقيقية | يُحدَّث يدويًا حاليًا (لا خادم مركزي يجمعه) |
| من يقدر يعدّل | حساب مدير بكلمة مرور | أي شخص يملك رابط اللوحة + GitHub Token |

## 1) إنشاء مستودع GitHub ورفع الملفات

اتبعي نفس خطوات "Codespaces" اللي شرحناها سابقًا:
1. أنشئي مستودع جديد على github.com باسم `mahka` (أو أي اسم تحبينه)
2. افتحيه → Code → Codespaces → Create codespace on main
3. من الشريط الجانبي ارفعي (Upload) ملف `mahka-static.zip`
4. في الطرفية:
```
unzip mahka-static.zip
shopt -s dotglob
mv mahka-static/* .
rmdir mahka-static
rm -f mahka-static.zip
git add .
git commit -m "مَحكى - النسخة الثابتة"
git push
```

## 2) تفعيل GitHub Pages

1. من صفحة المستودع → **Settings** → **Pages** (بالقائمة الجانبية اليسرى)
2. تحت **Build and deployment** → **Source** اختاري **Deploy from a branch**
3. **Branch**: اختاري `main` والمجلد `/ (root)`
4. اضغطي **Save**
5. انتظري دقيقة أو دقيقتين، وسيظهر رابط أعلى الصفحة شبيه بـ:
   `https://اسم-حسابك.github.io/mahka/`

هذا رابطك الدائم — يفتح لأي شخص، بدون نوم، وبدون أي تكلفة.

## 3) توليد GitHub Personal Access Token (مرة واحدة فقط)

هذا "المفتاح" يسمح للوحة التحكم بحفظ تعديلاتك داخل المستودع.

1. من GitHub، اضغطي على صورتك الشخصية أعلى يمين الصفحة → **Settings**
2. من القائمة اليسرى بالأسفل: **Developer settings**
3. **Personal access tokens** → **Fine-grained tokens** → **Generate new token**
4. اختاري:
   - **Repository access**: Only select repositories → اختاري `mahka`
   - **Permissions** → **Repository permissions** → **Contents** → اختاري **Read and write**
5. اضغطي **Generate token**
6. **انسخي التوكن فورًا** (يبدأ بـ `github_pat_...`) — لن يظهر لك مرة ثانية.
   احفظيه بمكان آمن مؤقتًا (مثل ملاحظة على جوالك) لحين استخدامه بالخطوة التالية.

⚠️ هذا التوكن بمثابة كلمة مرور لهذا المستودع تحديدًا — لا تشاركيه مع أحد.

## 4) الدخول إلى لوحة التحكم لأول مرة

1. افتحي: `https://اسم-حسابك.github.io/mahka/admin/`
2. عبّي:
   - اسم المستخدم/الحساب: `اسم-حسابك`
   - اسم المستودع: `mahka`
   - الفرع: `main`
   - Personal Access Token: الصقي التوكن الذي نسختيه
3. اضغطي **حفظ ودخول**

من هذه اللحظة، أي إضافة أو تعديل أو حذف تسوينه من اللوحة يُحفظ مباشرة في
مستودعك، ويظهر على الموقع العام خلال دقيقة تقريبًا.

## 5) إضافة أول قصة

1. من اللوحة → **التصنيفات** → أضيفي تصنيفًا واحدًا على الأقل
2. من تبويب **القصص** → **+ إضافة قصة**
3. عبّي العنوان والوصف، ارفعي الغلاف والملف الصوتي، اختاري **منشورة**
4. احفظي — افتحي الموقع العام بعد دقيقة وستجدين القصة ظاهرة للجميع

## 6) قيود يجب معرفتها

- **حجم المستودع**: GitHub يوصي بألا يتجاوز حجم المستودع الواحد 1GB. لو خططتِ
  لرفع عشرات الساعات من الصوت مستقبلًا، فكّري بترقية الاستضافة إلى حل مخصص
  للملفات الكبيرة (مثل Cloudflare R2 أو Backblaze B2) وربطه بنفس بنية JSON.
- **الأمان**: التوكن مخزَّن في متصفحك فقط (localStorage)، ولا يُرسل لأي مكان
  غير GitHub مباشرة. لكن لو استخدمتِ جهازًا عامًا/مشتركًا، اضغطي "قطع الاتصال"
  بعد الانتهاء من كل جلسة عمل.
- **تعدد المحررين**: لو أكثر من شخص يعدّل بنفس الوقت، قد يحدث تعارض في
  الحفظ (Merge Conflict) لأن كل تعديل Commit منفصل. مناسب لعمل شخص واحد أو
  اثنين بالتناوب، وليس فريقًا كبيرًا في نفس اللحظة.

## 7) التوسع المستقبلي

نفس مبدأ التصميم بالنسخة الكاملة يبقى صالحًا هنا: `data/settings.json` مرن
لأي نص جديد، و`stories.json`/`categories.json` منفصلان بعلاقة `category_id`
تسمح بإضافة جداول JSON جديدة لاحقًا (مفضلة، تعليقات، تقييمات...) دون كسر ما
هو موجود. عند الحاجة لحسابات مستمعين فعلية أو تفاعل بين المستخدمين، الأنسب
وقتها الانتقال لنسخة Flask الكاملة (المرفقة سابقًا) واستضافتها على خدمة
حقيقية، لأن الموقع الثابت لا يصلح لتخزين بيانات خاصة بكل زائر.
